## RC-002 — main Distill on Linux

- **Result:** Partially unblocked. Linux Distill v2.0.14 starts in a Debian 12 x86_64 guest under the available Docker/OrbStack emulation. RC-002 remains blocked because authorized configurable-model access and the required session/lifecycle proof are still unverified; credentials were not inspected and no provider request was made.
- **Environment:** macOS host; `distill --version` → `distill 2.0.14 (8e7101188723)`; Docker client/server `29.4.0/29.4.0`; cached `remotecode/computer:local` reports `linux/arm64`.
- **Action:** Ran the cached image with `--network none` and checked `command -v distill` inside it.
- **Observed at the original probe:** `Distill=unavailable`. Local Distill executables were all `macOS-aarch64` Mach-O binaries (versions 2.0.9, 2.0.13, and 2.0.14); `docker images` contained no Distill image. At that time `.sam-harness/config.yaml` set `network: false`, so no runtime or dependency was downloaded and no model was called.
- **ARM64 binary result:** After the user explicitly authorized network use, downloaded the official Distill v2.0.14 `distill-linux-aarch64` release asset; published SHA-256 `abf7e29c56c164476ea81ef6cc6a1b056620b154839c03de3db3ae9a66bb6864` matched. `file` identified an ELF 64-bit ARM aarch64 Linux executable. Mounted it read-only into `remotecode/computer:local` and ran it with networking disabled. The guest reported `aarch64`, glibc 2.36, and resolved dynamic libraries, but `distill --version` terminated with `Illegal instruction` (exit 132).
- **x86_64 runtime follow-up:** The official Distill v2.0.14 Linux x86_64 asset was checksum-verified earlier (SHA-256 `6e21372a858f7b563e038b6f0bdf3dd7da2e8d02f6cc9dfe2e9aca3b269e19a0`). The cached application image is ARM64 and did not support the first `--platform linux/amd64` attempt; executing the x86_64 binary in that ARM64 guest also lacked `/lib64/ld-linux-x86-64.so.2`. To isolate the architecture issue, pulled `debian:12-slim` after network authorization (image manifest digest `sha256:3783cc01769c7b2b1b83a5c5ad96c815348e28ed7da68e2e3687004faa906251`), mounted the binary read-only, and ran with `--network none --platform linux/amd64`. Both `distill --version` (`distill 2.0.14 (8e7101188723)`) and `distill --help` exited 0. Thus a Linux Distill runtime is available in an emulated amd64 Debian guest. The Debian image is only the runtime probe, not the planned RemoteCode guest/image; native target compatibility, model requests, and stdio-backed file-creation/interruption/restart/reconciliation are not established.
- **Remaining proof:** Obtain authorized configurable-model test access, then run the real session via the existing stdio interface and prove file creation, interruption, backend/process restart, and state/file reconciliation in the target-compatible Linux environment. No model credentials were inspected or model request made.
