How to use this backlog
Start

Open the task only after the IDs in “Depends on” have accepted evidence. “Start” describes the state that must exist.

Finish

“Delivery” is the requested behavior. “Proof” injects real failures when the operation can be ambiguous; attach result, environment, version, and artifact.

Fail

If any condition in “Fail if” occurs, the task returns to execution. Timeout does not prove rollback, and green CI does not replace real recovery.

Scope: Bot computer/browser for human intervention included. Generic browser/preview, Token Saver, and previous harnesses excluded. An unknown failure must end in an explicit and recoverable state, without automatic repetition of uncertain effect. No task authorizes deleting production data. Every task that adds or changes a workspace, Bot, thread, file, workspace-task, or Bot-routine route must prove that route's owner checks before acceptance; RC-012 remains the final audit across all such routes.
